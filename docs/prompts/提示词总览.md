# ai-article-agent 提示词总览

> 基于当前代码整理（`src/main/agent/` + Skills）。  
> 目的：一眼看清「哪一步调 LLM、system/user 说什么、还塞了哪些规则块」。  
> 长提示只摘硬性规则；完整文案以源码为准。  
> 按软件里的步骤名讲解工作流和提示词：[提示词说明-白话版.md](./提示词说明-白话版.md)。

---

## 1. 流水线一览

| 流水线 | 入口 | 主要 LLM 步骤 |
|--------|------|----------------|
| **文章创作 create** | `articleAgent.generateArticle` | 意图扩词 → E-E-A-T 萃取 → 写作简报 → 规划 → 大纲 → 分节撰写 →（结构检查）→ 词数校准 → SEO Meta |
| **文章优化 optimize** | `articleOptimizer.optimizeArticle` | 竞品缺口 → 诊断审计 → 大纲 enrichment → 分节优化撰写 → 词数 → Meta |
| **页面批量优化 batch** | `batchPageOptimizer.batchOptimizePage` | 单次就地优化整页 |
| **修订 revise** | `articleReviser` | 选区重写 / 全文按说明修订 |
| **插图匹配** | `articleIllustrationInserter` | 教程行号 ↔ 插图库 JSON |

**说明（创作）**：步骤⑧「润色」目前**不再调用 LLM**，仅做结构性检查（`runCreateStructureCheck`）。历史上的「降 AI 味」整篇润色已退出主路径。

## 2. 文章创作（create）

### 2.1 搜索意图扩词 · `analyzeAndExpandSearchQueries`

| | |
|--|--|
| **文件** | `searchIntent.ts` |
| **System 角色** | 资深 SEO 研究员：还原 Google 意图 + 生成调研搜索词 |
| **输出** | 仅 JSON：`intentSummary`, `searchIntentType`, `primaryKeyword`, `mustInclude`, `mustAvoid`, `queries` |

**硬规则摘要**

- 搜索词与主题语言一致；平台名（Spotify 等）可保留  
- **推广产品名禁止出现在 queries**  
- 受领域包 `searchHints` / `excludeQueryTerms` 约束  
- 4–5 条互不重复、偏博客/教程长尾  

**User 注入**：主题、语言、市场区域、用户 brief、推广产品（禁搜）

---

### 2.2 E-E-A-T 萃取 · `extractEeatInsights`

| | |
|--|--|
| **文件** | `articleAgent.ts` |
| **System** | 资深内容评估师（Google E-E-A-T） |
| **注入** | `getWritingPromptBlocks`（用户提及锁 + 主关键词块）、`getSkillsTextForStep('extract')` |

**User 要求抽取**

- 有数据/研究支撑的结论  
- 可引用框架（勿伪造人名机构）  
- 场景、痛点、误区  
- 竞品共性与缺口  
- 可选：`getExtractProductHint(产品名)`  

输入：`corpus`（竞品抓取正文）

---

### 2.3 写作简报 · `generateWritingBrief`

| | |
|--|--|
| **文件** | `writingBrief.ts` |
| **System** | 内容策略编辑：把萃取笔记压成写作简报 |
| **输出** | 仅 JSON：`intentOneLiner`, `keyFacts(8-12)`, `competitorGaps(3-5)`, `faqSeeds(3-5)`, `toneNotes`, `mustAvoid(3-6)` |

无可用萃取时走 `fallbackWritingBrief`（不调 LLM）。

---

### 2.4 规划 · `generateArticlePlan`

| | |
|--|--|
| **文件** | `articleAgent.ts` |
| **System** | SEO/GEO 内容策略师；**不要写正文/大纲** |
| **注入** | `buildPlanSkeletonRules`、写作块、`getSkillsTextForStep('plan')`、`articleLang.lock` |

**User 强制输出**（包在 `<thinking>…</thinking>`）

1. 搜索意图与痛点 ≤5 bullet  
2. 竞品要点整合 ≤5 bullet  
3. FAQ 问题句 3–5（无答案）  
4. Part 规划：How-to 须带 `layout:`；Review/Top 用名称+策略  

类型附加：`REVIEW_PLAN_GUIDANCE` / `TOP_LIST_PLAN_GUIDANCE`；有产品时按类型写植入规划句。

空规划会自动重试最多 2 次。

---

### 2.5 大纲 · `generateDifferentiatedOutline`

| | |
|--|--|
| **文件** | `articleAgent.ts` |
| **System** | 内容策略主编；**只输出结构骨架** |
| **注入** | `buildOutlineSkeletonRules`、`getFaqHeadingGuidance`、`getPrimaryKeywordOutlineHint`、`getPrimaryKeywordH1Hint` |

**骨架来源（三选一）**

- Top：`TOP_LIST_OUTLINE_SKELETON`  
- Review：`getReviewOutlineSkeleton(产品名)`  
- How-to GEO：Quick Answer → Intro → 通用 Part → 产品 Part → FAQ → Conclusion  

**硬规则**

- 首行 `# SEO H1`（不得与 Topic 逐字相同）  
- 仅 `##`/`###` + 短 bullet；禁止成稿段落  
- How-to：落实规划中的 layout；产品 Part 仅一节含 Why + Step stub  

后处理：`enforceOutlineSkeleton` + `enrichOutlineMethodModes`。

---

### 2.6 分节撰写 · `draftBySections`

| | |
|--|--|
| **文件** | `articleAgent.ts` |
| **System（Review）** | 专业测评作者；经验写正文，禁 Real-World / Hands-On 等口号 H2 |
| **System（其他）** | 领域专家；体现 Experience & Expertise |
| **稳定注入** | `PLAIN_PROSE_STYLE_GUIDANCE`、`VOCABULARY_STYLE_GUIDANCE`、语言锁、主关键词块、Skills 节选 + 结构块（字数/GEO/Review/Top，**不含**产品提及补充） |

**User 按节动态拼接**（节选）

| 节类型 | 提示来源 |
|--------|----------|
| Intro / Conclusion | `getIntroConclusionSectionHint` |
| FAQ | `getFaqSectionHint` |
| Quick Answer | `getDraftQuickAnswerHint`（How-to：QA 不点名产品） |
| Review 各节 | `getReviewSectionDraftHint` |
| Top 榜单 / Also Worth | 内联榜单/补充推荐规则 |
| GEO 通用 Part | `getDraftGenericPartHint` |
| 产品 Part | `getDraftProductPartHint` |
| 对比表 | 内联 Markdown 表规则 |

另含：相邻大纲上下文、`formatWritingBriefForSection`、本节词数目标、`getPrimaryKeywordSectionHint`、按节产品提及锁。

文首 H1：`resolveArticleH1(outline, topic)`，**不再**硬编码 `# ${topic}`。

---

### 2.7 结构检查（原「润色」步骤，无 LLM）

`runCreateStructureCheck` → `checkArticleStructure`：校验格式与大纲章节对齐。

---

### 2.8 词数校准

| 场景 | 文件 | 提示要点 |
|------|------|----------|
| 超上限删减 | `articleWordEnforcement.ts` | JSON 补丁：只删重复/低价值句，不改标题 |
| 分节扩写/删减 | `articleLengthPatch.ts` | `insert_after` / `delete` 补丁；只改本节 |
| 大幅消减 | `articleLengthPatch.ts` | 压缩到目标词数并理顺衔接；不新增事实 |

---

### 2.9 SEO Meta · `generateSeoMeta`

| | |
|--|--|
| **文件** | `seoMeta.ts` |
| **System** | SEO specialist + `SEO_META_GUIDANCE` + 语言锁 |
| **User** | Topic（勿原样当 title）、H1（禁止 verbatim）、可选产品名、**文章摘要**（非全文） |
| **输出** | 仅 JSON：`metaTitle` / `metaDescription` |
| **上限** | Title ≤60、Description ≤160；`max_tokens` 与步骤 cap 相关 |

摘要：`buildArticleSummaryForSeoMeta`（H1 + Quick Answer / Intro / Overview / Conclusion / FAQ 节选，≤2200 字符）。

## 3. 文章优化（optimize）

### 3.1 竞品缺口 · `extractCompetitorGapInsights`

**System**：SEO/GEO 竞品分析专家 + 用户锁 + Skills  

**User 结构**

- KEEP + ENHANCE / ADD / REMOVE+REPLACE  
- 按 H2 索引块  
- 原页面 ≤12k、竞品语料 ≤48k  

---

### 3.2 诊断审计 · `auditSourcePage`

**System**：内容诊断专家；**how-to/教程默认保留**；禁止无证据整段删除教程；注入 `getEditorPromptBlocks`（含可读性等）

**User 要求长报告**：现状、优质清单、缺口、删减、结构 SEO/GEO、局部改写、动作清单、大纲骨架、`[NEW H2]`、按 H2 编辑要点，并以机器可读 **`OPTIMIZE_SECTION_CONTRACT` JSON** 收尾。

合同解析失败会触发修复再请求（同文件内 repair 调用）。

---

### 3.3 大纲 enrichment · `enrichAnchoredOutline`

**System**：在各 ## 下补 KEEP/ADD/REMOVE bullet；**严禁改 ## 标题**；仅可补诊断中的新增 H2。

---

### 3.4 分节优化撰写 · `draftOptimizedSections`

**System 前缀**：`buildOptimizeDraftSystemPrompt`（动作类型、语言、词数区间、mention、Skills、editorBlocks）

**User**：本节动作提示（`getOptimizeSectionActionHint` / 产品相关变体）、节 briefing 摘录、原文配对节等。

动作类型大致包括：就地润色、有限增删、新写模块等（见 `optimizeStructure.ts`）。

其后仍可走词数校准与 SEO Meta（与创作共用或同类逻辑）。

---

## 4. 页面批量优化（batch）

| | |
|--|--|
| **文件** | `batchPageOptimizer.ts` → `optimizeScrapedPage` |
| **System** | 资深 SEO/GEO 编辑；遵循 Skills；**仅 Firecrawl 正文，无 Tavily**；`CONTENT_READABILITY_GUIDANCE` |
| **User** | 就地优化完整 Markdown；保留 H2/H3 顺序与语言；直接出正文 |

Skill：通常为 `page-batch-optimizer`。

---

## 5. 修订（revise）

### 5.1 选区重写

**System**：精确 Markdown 局部编辑；只输出替换片段；整段删除输出 `[[DELETE]]`。

### 5.2 全文修订

**System**：按说明改、非从零创作；未提及部分尽量保留；输出完整 Markdown。

空结果会追加一轮「必须输出删除后全文」的纠正对话。

---

## 6. 插图匹配

**System**：插图匹配助手；只输出 `[{"id","afterLine"}]`；每 id 最多一次；优先步骤行。

**User**：产品名、带行号的教程、插图库目录。

## 8. Skill 注入（`skillPipeline.ts`）

### 8.1 启用 Skill（创作相关）

| Skill ID | 用途 |
|----------|------|
| `streaming-audio-domain` | 流媒体领域、关键词、E-E-A-T |
| `streaming-audio-compliance` | 禁词、免责、合法边界 |
| `seo-geo-streaming-top` | Top 榜单领域要点 |
| `product-review` | Review 领域要点 |
| `seo-geo-streaming-audio` | 兼容壳（已拆分） |
| `seo-geo-ios-security` | iOS 安全类 |
| `article-optimizer` | 优化模式专用 |
| `page-batch-optimizer` | 批量优化专用 |
| `explainer-voice` / `humanizer` | 文风（按步骤 append） |

路径：`.cursor/skills/<id>/SKILL.md`（开发）与 `src/main/bundled-skills/<id>/`（打包）。

### 8.2 按步骤注入策略（摘要）

| 步骤 | 行为 |
|------|------|
| `extract` | Review：节选原则/合规；Streaming：compliance + domain（+ top） |
| `plan` | 偏好规划/FAQ/榜单等小节，截断约 900–1000 字 |
| `outline` | **不注入** Skill 全文（结构靠代码骨架） |
| `draft` | 按节 `pickSkillFragmentForSection` + `draftStructureBlock` 摘要 |
| `polish` | 仅 compliance/风格短摘（创作主路径已不调 LLM 润色） |
| `length` | 不注入 Skill |
| `optimize` | optimizer / review 等截断注入 |

文章类型与 Skill 同步见 `skillManager.syncCreateSkillsForArticleType`（how-to / review / top-rank）。
