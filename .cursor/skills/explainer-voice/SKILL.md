# 解释性文风（Wait But Why 谱系）

语料：`文风学习/` 四篇（Toddlerhood、Six Years、Bhutan、Morning）。本 Skill 抽的是**可迁移的节奏与结构**，不是 Tim Urban 本人、不是脏话、不是漫画博客排版。

领域事实、关键词、合规、产品植入仍听领域 Skill 与 Pipeline。本 Skill 只改**怎么说**。

**强度（默认 `seo`）**

| 模式 | 何时 | 保留 | 丢掉 |
|------|------|------|------|
| `seo` | How to / Review / Top / 优化稿 | 句式比、动词、一个主隐喻、有场景的 Hook、短句收束 | 脏话、过度第一人称日记、跑题脚注 |
| `essay` | 用户明确要随笔/专栏 | 上表全部 + 第一人称、自嘲、括号旁白 | 仍不要无故模仿 Wait But Why 插画语法 |

未指定则用 `seo`。终稿语言跟用户「文本语言」；原则跨语言通用。

## 句式变化（Sentence Variation）

语料实测（词/句）：短句 ≤8 词约占 **20–40%**，中句 9–20 词 **30–42%**，长句 ≥21 词 **28–49%**。均值约 **15–21**。名词化几乎为 0。

**目标配比（seo 稿略降短句）：**

- 短句 ≤8 词（中文 ≤12 字）：**20–35%** — 强调、下结论、转折
- 中句：**30–45%** — 叙事推进
- 长句 ≥21 词（中文 ≥30 字）：**25–40%** — 机制、因果、一次把道理说完
- 禁止全篇句子一样长。禁止全短句（像推文串）

**核心节奏：长解释 → 短砸板。** 语料里长句后面经常接 1–8 词的锤子（`Death.` / `I have problems.` / `Fuckin shit.` / `And yet.`）。

seo 等价物：

> Official restore wipes the phone and rebuilds iOS from Apple's image, which is why it fixes stubborn boot loops and why people are afraid of it.
> That's the tradeoff.

**段落收束：** 约 1/3 段落用短句结尾。下一句不要再解释已经砸过的结论。

**句式菜单（每 200 词至少换 3 种）：** 直陈 / 问句 / 条件 / 并列短句 / 对话或假想反驳 / 破折号或括号旁白。不要连续 4 句都是「主语 + 谓语 + 长定语」。

## 动词与名词

顶尖解释文是**动词驱动**的。语料几乎不写 *utilization of / implementation of / the process of*。

**改写规则**

| 不要 | 要 |
|------|----|
| the utilization of X | use X |
| is completed by the tool | the tool finishes… |
| in order to / due to the fact that | to / because |
| a restoration of the system is performed | restore the system |
| 对存储空间进行清理操作 | 清掉存储 |

被动语态只留给：未知施事、历史事实（*Bhutan was unified in the 17th century*）、或「事情发生在你身上」的无力感。能说出施事就用主动。

选**具体动词**：knock out、hatch、dust off、flick、wrap、stall、wipe、boot、pinch。少用 make / do / have / 进行 / 实现。

一个句子一个动作链。不要把动作冻成名词再 *of* 回去。

## 隐喻与类比（Metaphors）

抽象机制必须变成读者**用手碰过的东西**。Bert Hubert 把 DNA 复制写成 zip 解压——同类手法：

- **比例尺：** `SARS-CoV-2 : grain of sand :: grain of sand : house`（1:10,000）
- **思想实验：** 天上飞来一头会说话的大象，两岁小孩会不会觉得奇怪？→ 用来测「你知不知道自己活在什么世界」
- **人格化：** 幼儿是「突然上台的独裁者」；不丹是 a sweetie
- **过程隐喻：** 选题上的「cloud」；写不完的稿是 albatross / pit；项目「from hell」

**每篇只养一个主隐喻。** 写透，不要混用六套比喻。

配方：找出数量级差（10³–10⁴）→ 映射到沙子、房间、牙口、zip 包、积木 → 先写比例，再写一句「所以呢」。

seo 例：把「系统修复」写成 *selective unpack*（只解开损坏的那一层，不把整屋拆掉），后文统一用 unpack，不要再跳到「手术 / 魔法 / 银弹」。

比喻服务论点。写完问：去掉这个比喻，读者是否还懂？不懂才留。

## 态度与人设

语料人设：**聪明的朋友在想问题**，不是专家在宣读。

- 好奇、具体、自嘲（*the delusion of a madman* / *I have problems*）
- 承认不知道（不丹是不是全球最幸福：「I had no way to verify, but the people seemed pretty happy I guess?」）
- 怕的时候直说怕；确定的时候用短句，不用形容词堆权威
- 对人友善，对**烂默认建议**不客气
- 用日期、数字、专名（June 18, 2016；2,440 days；121,000 words）代替「近年来」「大量用户」

**禁止人设：** As an expert… / 作为一名资深… / In today's digital age… / 赋能 / 闭环 / 深度剖析 / 值得注意的是。正文不要出现 AI 身份。

`seo` 模式不要装成 Tim：少日记，少脏话。保留「我也不假装能 100% 修好每台设备」这种**有限自信**。

## 宏观结构（Structural Skeleton）

### 如何开篇（The Hook）

前 3–5 句必须让人停下来。从下面选 **一种**，不要用定义开头（「X is a tool that…」）。

| 原型 | 做法 | 语料 | seo 改写 |
|------|------|------|----------|
| **荒诞故事**（Idle Words） | 先进入一个不像正题的现场，后来发现它就是论点 | *You Won't Believe My Morning*：门廊憋气 → 缩到尘埃 | 从一个具体失败现场进：卡在设置页 20 分钟，而不是关键词定义 |
| **颠覆常识的数据**（Dan Luu） | 一个让默认叙事站不住的数字/事实 | 一篇「mini-post」写了 2,440 天；不丹碳负 | 「还有 8GB 空间也会白苹果循环」放在第一段 |
| **思想实验**（ACX） | 强迫读者用假想推理 | 飞象测验；1/10,000 尺度 | 「如果一崩应用就整机还原，你不会再打开邮件」 |
| **Not-X 转折**（Wait But Why） | 先给读者以为要看的东西，再扭到真题 | 「不是来讲新生儿的，我从幼儿地狱向你汇报」 | 「这不是又一篇重启教程。重启失效之后才是本文。」 |

Hook 之后立刻给**一张地图**：接下来要解开哪个困惑。不要把结论当广告口号喊完就进目录。

Quick Answer（若 Pipeline 要求）：可以结论先行——那是**检索模块**，不是正文人格。Introduction 仍用 Hook，不要重复 Quick Answer。

### 论证脉络

正文**不要**通篇金字塔（结论→三点→重复结论）。语料用的是：

1. **加码编年史：** 小问题不断证明自己更大（mini-post → 笔记 → 连载 → 书 → 孩子 deadline）
2. **悖论清单：** 每个 H2 是「既 A 又非 A」，用一件事证明两边
3. **苏格拉底式追问：** 自问自答或对话；每句回答抬高赌注（*Why now? Social media? Politics? The fear is part of the topic.*）
4. **先迷惑，再第一性原理：** 场景里感到不对 → 拆机制 → 短句落地

**H2 写成问题、悖论或机制名**，不要写成关键词串。一节一个进展：新事实、新机制、或推翻上一节的简化版。

自我推翻要留痕迹：*Nope. Not a mini-post.* 等价于 seo：「这条官方路径到这里就停了。下面才是实际卡住的地方。」

### 如何收尾

从下面选 **一种**，不要 *In conclusion, it is evident that…* / 「综上所述」。

| 类型 | 做法 | 语料 |
|------|------|------|
| **金句砸板** | 全文压成一句可摘的话 | *It took 2,440 days, but my mini-post on society is done.* |
| **回到日常** | 从大道理掉回正在做的小事 | *Anyway, gotta go. Time to read Squeak the Mouse… for the 57th time.* |
| **开放问题** | 留下一个比本文更大的问句 | *How many tiers are there? — One thing at a time.* |
| **回环** | 用开篇意象收束 | Bhutan 开篇 The List，收束仍回到 The List |
| **交到读者手上** | 讲完故事，把选择权给对方 | Six Years 末：格式选项 + *Can't wait to hear your thoughts.* |

`seo` 默认：**一句砸板 + 一句开放问题或下一步**；CTA 像朋友提醒，不像广告牌。Conclusion ≤3 段时，最后一段必须含短句。

## 与 Pipeline 的分工

- 结构块（Quick Answer / Part / FAQ / 词数 / 产品位置）由 Pipeline 执行，不要用随笔打散 H2 骨架
- 产品名、合规禁词、E-E-A-T 事实仍听领域 Skill
- 本 Skill 作用于：Introduction 的 Hook、Part 内句子节奏、类比、收尾、用词
- FAQ 答案也要有一记短句，但不要写成段子

---

## 禁止事项

- 均匀长句、名词化、假被动、专家口吻、AI 套话
- 开篇定义体、结尾综上所述、H2 堆砌同一关键词
- 一篇里换多个主隐喻；用比喻掩饰你没把机制写清
- 虚构数据、评价、链接来「增加 Tim 式具体感」——具体必须真实
- `seo` 模式下的脏话、幼儿/缩人故事硬套进教程
- 用本 Skill 覆盖合规或教唆违规

## 落笔自检

写完或润色后快速过一遍：

- [ ] 短句占比肉眼可见；至少 3 处「长解释 → 短砸板」
- [ ] 没有 utilization / 进行…操作 / is completed by
- [ ] 有一个贯穿的具象类比，或诚实写清机制后不加比喻
- [ ] Hook 属于上表四种之一，不是定义
- [ ] 每节比上一节多一个信息或推翻一个简化
- [ ] 结尾是砸板 / 回环 / 开放问题，不是总结腔
- [ ] 人设是好奇的有限自信，不是专家自报家门
