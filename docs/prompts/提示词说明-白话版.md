# 工作流与每一步的提示词

步骤名用软件里的叫法：进度板上的任务名，以及生成时状态栏里的那一行。提示词仍分两段——**系统提示**（角色、格式、硬规则）和**用户消息**（这一步的材料与任务）。源码不发给模型。写作指南（Skill）只摘当前步骤用得到的片段。

文章类型在界面上是 **How to**、**Review**、**Top rank**。三条类型共用文章创作这条流程，从「内容规划」开始按类型分叉。

---

## 一、文章创作

大纲出来之前，进度板只有三项：**调研资料**、**内容规划**、**生成大纲**。大纲出来之后，进度板改成大纲里的各个章节。状态栏比进度板更细，顺序如下。

| 状态栏 | 进度板 | 是否请模型 |
|--------|--------|------------|
| 加载 Skills | 调研资料 | 否，只读取写作指南 |
| ② 搜索意图分析 & 拆解搜索词 | 调研资料 | 是 |
| ③ 搜索与抓取（Tavily / Firecrawl） | 调研资料 | 否 |
| ④ E-E-A-T 信息萃取 | 调研资料 | 是 |
| ④b 生成写作简报 | 调研资料 | 是；没有萃取笔记时程序自己填 |
| ⑤ 分析与规划（搜索意图 / FAQ / 大纲构思） | 内容规划 | 是 |
| ⑥ 生成差异化大纲 | 生成大纲 | 是，之后程序再收一遍格式 |
| ⑦ 分段撰写正文 | 各章节标题 | 是，一节一次 |
| ⑧ 结构性检查：格式与大纲章节 | 结构性检查… | 否 |
| ⑨ 词数校准 | 词数工作台 | 超出区间或某一节偏差时才请模型 |
| 内链：在正文中匹配可链接短语 | — | 否 |
| ⑩ 生成 SEO Meta Title & Description | — | 是 |

未配置 Tavily / Firecrawl 时，状态栏写「跳过调研阶段」，写作简报改由程序按主题填写。勾选复用上次调研时，跳过搜索意图和搜索抓取，状态栏写「复用上次调研结果」。

成稿之后，进度板上的 **去 AI 味** 不在这条流程里，见文末。

### How to / Review / Top rank 从规划开始的差别

- **How to**：规划里每个 Part 要标 `layout`。大纲是 Quick Answer → Introduction → 通用 Part → 一个产品 Part → FAQ → Conclusion。
- **Review**：被测评产品占主体。Overview 必选，其余 Part 按调研增减。有推广产品时，在对比表上方加 Alternative Part。
- **Top rank**：按名次写 N 个产品。推广产品符合 Topic 则排第 1；不符合则放 Also Worth Considering，不进主榜。

## 四、文章创作的提示词

### ② 搜索意图分析 & 拆解搜索词

**输出：** `intentSummary`、`searchIntentType`、`primaryKeyword`、`mustInclude`、`mustAvoid`、`queries`（4–5 条）。不要 markdown 说明。

**系统提示：**

> 你是资深 SEO 研究员，擅长从用户输入中还原真实 Google 搜索意图，并生成用于竞品博客调研的搜索词。

顺序：先判断意图类型（informational / how-to / comparison / transactional / review），再提炼 primaryKeyword、用户目标、必须覆盖的概念和应避开的方向，最后写搜索词。

规则：

- 搜索词语言与主题一致。
- 主题中的平台、服务、场景名保留（Spotify、Apple Music、World Cup、MP3）。
- 有领域包时，优先覆盖 `searchHints`，禁止引入 `excludeQueryTerms`（主题原文已出现的除外）。
- 指定推广产品名只用于成文，不得出现在 `queries` 中。
- 搜索词紧扣 primaryKeyword，禁止漂到相邻主题。提示里的例子：主题是世界杯歌曲下载，不要搜成世界杯赛程或球员介绍。
- 每条 query 像真实用户的长尾词，可含 how to / guide / tutorial / blog / step by step / best way。
- 避免搜单曲、歌单、官方公告、纯新闻快讯。

**用户消息：** 主题、输出语言、目标市场、补充说明。有推广产品时写「禁止出现在 queries 中」并带上产品名。最后一句：请先分析搜索意图，再输出 JSON。

### ④ E-E-A-T 信息萃取

没有抓到正文时不请模型，记一句「未抓取到可用正文，将基于主题与 Skills 直接创作。」

**输出：** Markdown 分条笔记，供后面写大纲。内部分析，中文或英文均可，事实和论点须能译进成稿。

**系统提示：**

> 你是资深内容评估师，熟悉 Google E-E-A-T 原则（Experience, Expertise, Authoritativeness, Trustworthiness）。

附上用户补充要求、产品提及锁，以及本步的 Skill 节选，标题为「写作规范参考」。

**用户消息：** 阅读竞品页面，提取：

- 有数据/研究支撑的结论
- 可引用的专家观点或方法框架（勿伪造具体人名机构）
- 真实场景案例、用户痛点、常见误区
- 竞品文章的共性套路与内容缺口

忽略水词、同质化废话、硬广、导航残留。同时放入主题、主关键词提示、补充说明、后续成文语言，以及抓取正文。有产品名时加 `getExtractProductHint`。

### ④b 生成写作简报

萃取为空或是「未抓取」时不请模型，走 `fallbackWritingBrief`。

**输出：** `intentOneLiner`、`keyFacts`（8–12）、`competitorGaps`（3–5）、`faqSeeds`（3–5）、`toneNotes`、`mustAvoid`（3–6）。

**系统提示：**

> 你是内容策略编辑。将 E-E-A-T 竞品萃取笔记压缩为「写作简报」，供后续规划与分段撰写复用。

保留可写进正文的事实与差异化角度，删除导航残留与水词。

**用户消息：** 主题、成文语言、搜索意图分析、补充说明、萃取原文（截到约 8000 字）。

后面的内容规划、生成大纲、分段撰写不会重发整份笔记，只放简报摘要。分段撰写用的是更短的一截：写作意图、最多 8 条事实、最多 4 条差异化、最多 4 条本节须避免。

### ⑤ 分析与规划

进度板上这一步叫 **内容规划**。聊天里的标题是「创作规划」。

**输出：** 包在 `<thinking>…</thinking>` 里。必须出现在可见回复中，不能只写在内部推理里。不要写正文，不要写 `##` 大纲。返回为空时，同一套提示再请求，最多 2 次。仍为空则用占位句「规划步骤未返回内容，将基于写作简报继续。」

**系统提示：**

> 你是 SEO/GEO 内容策略师。完成内部分析与规划，不要撰写正文或章节大纲。

加上语言锁，以及规划格式：

- bullet，每点短，总篇幅约 400–600 英文词。
- FAQ 只列 3–5 个问题句，不写答案。
- How to：每个 Part 必须带 `layout:`。取值只有 `multi-method`（≥2 种可独立执行的操作）、`narrative`（原理、背景、单一论点）、`product-tutorial`（全文仅一个「产品推荐 + 分步教程」）、`comparison`（维度对比）。行格式：`Part N · [标题意图] · layout: <type> · [1 句目的]`。
- Review / Top rank 不标 layout，只写 Part 名称 + 1 句目的。

用户补充要求、产品提及锁、本步 Skill 节选（「领域写作要点」）也在系统提示里。

**用户消息**四块：

1. 搜索意图与读者痛点（≤5 bullet）
2. 竞品/行业要点如何整合（≤5 bullet）
3. 3–5 个 FAQ 问题句（无答案）
4. How to 写带 layout 的 Part 规划；Review / Top rank 写各 Part 名称 + 差异化策略

另附主题、主关键词提示、补充说明、写作简报摘要、终稿词数区间（How to / Review 约 1000–1800 词，Top rank 约 1200–2000 词）。

按类型多附一段：

- **Review（`REVIEW_PLAN_GUIDANCE`）：** 被测评产品占正文约 60–70%。Overview 必选，其余 Part 按产品性质与调研灵活确定。有用户产品时再规划 Best Alternative 专属 Part + 对比表 + FAQ。禁止 Overview 过薄就跳到 Alternative。Part 名称勿用 Real-World / Hands-On / Experience。
- **Top rank（`TOP_LIST_PLAN_GUIDANCE`）：** 从 Topic 解析 N，不足则默认 10。顺序：Quick Answer（勿点名推广产品）→ Introduction → 选型标准 → Top N → 可选对比表 → FAQ → Conclusion。为 N 个席位各规划 1 个真实工具，并注明用户产品是否符合准入及排位。
- **How to 且填了产品：** 各用 1 句规划通用 Part 与产品 Part 的位置和目的。

### ⑥ 生成差异化大纲

进度板上这一步叫 **生成大纲**。

**输出：** 结构骨架。首行 `# SEO 标题`，其后 `##` / `###` 加短 bullet。禁止段落与成稿文案。程序再用 `enforceOutlineSkeleton` 清掉漏进去的正文，并用 `enrichOutlineMethodModes` 补 method mode。

**系统提示：**

> 你是内容策略主编。只输出文章结构骨架，不要写正文。

格式（`buildOutlineSkeletonRules` + H1 规则）：

- 第一行必须是 `# …`，含主关键词的核心词或自然短语，**不得与 Topic 逐字相同**。可加年份、Best/Top、Guide/Compared。英文宜 8–14 词，中文宜 15–28 字。优先 How to / Fix / Set Up / Use；少用 Detox、Retrain、Journey，除非 Topic 原文就是这些词。
- 只允许标题 + bullet（每条 ≤20 英文词或 ≤35 中文字）。
- multi-method 的每个 `###` 下，首行必须是 `- mode: procedural|explanatory|checklist|caution`，再跟 1–2 条 stub。narrative 的 `##` 下只有 3–4 条 bullet，禁止 `###`。
- 禁止完整段落、Pros/Cons 正文、分步教程细节、FAQ 答案、对比表单元格、引言/结论正文。
- FAQ 的 H2 与主题相关，不要只写孤立的 FAQ。下面 3–5 个问句，不写答案。
- Quick Answer / Introduction / Conclusion 各 2–3 条 bullet。
- 大纲本身约 600 英文词以内。终稿目标词数写在规则里。不要复述 Skill 全文，不要输出 `<thinking>`。
- 用户消息里若有「规划 Part layout」，layout 类型不可改。`product-tutorial` 展开为 `### Why …` + `### Step-by-Step Tutorial`（≥4 step bullets）。`comparison` 只列维度名或表头。

本步不注入 Skill 全文。

**用户消息：** 主题、补充说明、对应骨架、规划摘要（截到约 2400 字）、写作简报。How to 会把规划里的 layout 行原样贴上，并写「硬性约束，逐条落实」。

三种骨架：

- **How to：** `# SEO H1` → Quick Answer → Introduction → 2–3 个通用 Part（按规划 layout 展开）→ 1 个产品 Part（`layout: product-tutorial`）→ FAQ（仅问题）→ Conclusion（2–3 bullets）。产品教程 stub 只出现在那一个 Part。
- **Review：** `# SEO H1` → Quick Answer → Introduction → Overview（必选）→ 按调研增补的可选 Part → `## The Best {topic} Alternative: {产品名}`（3–4 bullets）→ 对比表（1 bullet 列维度）→ FAQ → Conclusion。Alternative Part 必须紧挨在对比表上方。H2 按内容命名，禁止 Real-World / Hands-On / In My Experience / Authentic Experience。
- **Top rank：** H1 含 Top N 与品类词，不得与 Topic 逐字相同。Quick Answer 不写推广产品全名。Introduction 2–3 bullets。Part 1 How We Picked 3–5 bullets。Part 2 只写产品 stub：`### N. [Product] — [≤8 词 verdict]`，其下最多 2 条 bullet，禁止 Pros/Cons 正文。可选 Comparison、Also Worth Considering。FAQ 仅问题。Conclusion 2–3 bullets。符合准入的用户产品固定为 `### 1`。

### ⑦ 分段撰写正文

每一节单独请求一次。系统提示在各节之间保持同一份；本节特有的规则放在用户消息。

**输出：** 只输出本节 Markdown 正文，不要输出 `##` / `###` 本节标题行，不要重复大纲。程序把标题加回去，按大纲顺序拼接。文首 H1 用大纲首行（`resolveArticleH1`），不再写成 `# ${topic}`。

**系统提示：**

- Review：

> 你是该领域专业测评作者：经验与判断写在正文细节里，勿用 Real-World / Hands-On / In My Experience 等口号化标题自我证明。

- How to / Top rank：

> 你是该领域专家作者，写作需体现 Experience 与 Expertise。

然后是语言锁、`PLAIN_PROSE_STYLE_GUIDANCE`、`VOCABULARY_STYLE_GUIDANCE`，以及该类型的结构块（字数、`GEO_ARTICLE_STRUCTURE` 或 Review 结构或 `TOP_LIST_ARTICLE_STRUCTURE`）。

文风块的要点：先写事实、步骤和场景；比喻少用；用具体的能做什么、不能做什么建立信任。用词块的要点：H1–H3 写出任务、场景或结果；动词用 skip、hide、create、connect、switch 这类，不用 weaponize、leverage、supercharge；Topic 抽象时写成读者实际做的事，不要改写成 Detox / Retrain 这类包装。

产品提及锁不放进系统提示，只放进该节的用户消息。

**用户消息**按节拼接：

- 本节的产品提及锁、主关键词块、本节 Skill 节选
- 文章主题、输出语言、补充说明
- 大纲上下文：上一节、本节、下一节（相邻节正文截到约 280 字）
- 写作简报的本节可用要点
- `请撰写本节「{标题}」`、本节要点、本节词数目标、全文须在词数区间内
- 无单段字数上限。若需增字，补充对读者有用的实质内容，禁止水字数。

按节追加的提示：

| 节 | 提示要点 |
|----|----------|
| Introduction / Conclusion | 词数与段数上限（Introduction、Conclusion ≤150 词、≤3 段） |
| FAQ | 问答写法，整节有词数上限 |
| Quick Answer | 直接回答；How to / Top rank 不点名推广产品 |
| How to 通用 Part | 讲做法；产品名只在内容自然相关时出现 |
| How to 产品 Part | Why + Step-by-Step，只在这一节写教程 |
| Review 各节 | 具体、可验证、有场景；被测评产品章节须写足 |
| Top rank 榜单 | 每条独立 `###`：简介、**Pros**、**Cons**、**Best for**、关键参数。符合 Topic 的用户产品为 `### 1` 且篇幅略长。禁止合并成一段 |
| Also Worth Considering | 适用场景、与 Topic 的差异、为何未进主榜 |
| 对比表 | Markdown 表格，至少 5 个维度；表后 1–2 段说明为何推荐我方产品 |

知识库按产品名匹配。只在介绍该产品的那一节注入；匹配到时状态栏写「已读取知识库」。

### ⑧ 结构性检查

不请模型。对照大纲检查格式和章节是否对齐。失败时保留完整正文并继续，状态栏写「结构性检查失败，已保留完整正文」。

### ⑨ 词数校准

已在区间内则不请模型。请模型时不交整节新正文，只交补丁 JSON，程序用 `find` 在原文里唯一匹配后再套用。

**偏长，只删除**（`buildDeleteOnlyPatchSystemPrompt`）：

> 你是文章长度编辑。文章偏长，只允许删除重复或低价值原句。

只允许 `{"ops":[{"op":"delete","find":"原文原句"}]}`。禁止 replace、insert_after、改标题、重写段落。不要删整节，不要删仍可用的操作步骤。没有安全可删的句子则 `{"ops":[]}`。

**某节偏短，只插入**（`buildInsertAfterPatchSystemPrompt`）：

> 你是文章长度编辑。本节偏短，只允许在原句之后插入实质内容。

只允许 `insert_after`。`with` 是 1–3 句实质补充（操作细节、例子、注意点、适用场景）。禁止空话、重复、delete、replace、改标题、改表格、改 `[Image: …]`、改步骤编号。

**大幅消减某一节：** 压到目标词数并理顺衔接，不新增事实，只改这一节。

用户消息含主题、章节名、当前词数、目标词数、本节原文。状态栏示例：「为「某节」补大约 N 词」「高于上限，仅删除重复句」。

低于下限时不扩写全文，状态栏写「低于 {min}，不扩写全文」。

### ⑩ SEO Meta Title & Description

**输出：** 仅 JSON：`{"metaTitle","metaDescription"}`。

**系统提示：**

> You are an SEO specialist writing page meta tags for search engines (Google).

`SEO_META_GUIDANCE`：

- Meta Title 50–60 字符；primary keyword 靠前；具体，不要标题党。
- 措辞必须不同于文章 H1，是 SERP 用的短标题，不能复制粘贴。
- Meta Description 140–160 字符；概括核心价值，primary keyword 出现一次，结尾可有轻微 CTA；无 HTML。
- 语言与正文一致。
- 不要把 Meta Title 原句再放进 Description。

**用户消息：**

- `Primary keyword context (for wording — do not paste unchanged as meta title): {topic}`
- `Article H1 (must not copy verbatim): {H1}`
- 相关时带产品名
- 只根据文章摘要写一条 Title、一条 Description

摘要由 `buildArticleSummaryForSeoMeta` 从 H1、Quick Answer、Introduction、Overview、Conclusion、FAQ 节选，≤2200 字符，不传全文。

若 Title 与 Topic 或 H1 重复，同一套系统提示再请求一次，并加上：上一次 meta title 与关键词/H1 重复，请改成不同的 SERP 措辞，同时保留关键词。

## 五、文章优化的提示词

### ⑤ 竞品缺口分析

未抓到竞品正文时不请模型。

**系统提示：**

> 你是 SEO/GEO 竞品分析专家。对比「待优化原页面」与「竞品高排名页面」，输出可执行的内容评估清单（保留增强什么、补充什么、删减什么）。

附用户补充要求与优化 Skill。

**用户消息**三段，并放入原页面与竞品正文（原页面、竞品各有长度上限）：

- **KEEP + ENHANCE：** 原文仍准确、可用、体现经验/专业性的段落，注明章节，以及可补哪些竞品要点。

### 去 AI 味
